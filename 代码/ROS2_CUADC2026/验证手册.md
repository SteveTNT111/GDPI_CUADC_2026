2. 读 `错题本.md` PRE-FLIGHT + 全部错题条目。
3. 读源文件全文（分段读完 100%，不许只读一半）+ 上一个已验证译本（对齐模式）。

## 3. 写验证脚本 `scripts/verify_cX.py`（模板 = verify_c1.py）

结构固定 5 段：

1. **预检导航辅助话题**（compass_hdg / rel_alt / fix，缺流 → 跑 `request_streams.py`
   重试一轮）；缺失直接 FAIL 退出（脚本必然卡死在数据等待）。
2. **扮演操作者**（按被测脚本的安全契约决定）：
   - 契约是"脚本绝不碰 arming"（如 C1）→ 验证脚本负责 set_mode GUIDED + arming；
   - 契约是"脚本自己解锁"（如 C2）→ 验证脚本不碰 arming，只喂授权输入
     （subprocess stdin=PIPE，等日志出现授权提示后写 `YES\n`）。
3. **拉起被测脚本**：`python3 install 产物` 直跑（避开 ros2 run 图发现延迟撞
   SITL 地面自动上锁窗口），日志落盘 `/tmp/opencode/cX_run.log`（#4：tee 落盘）。
4. **全程采样** state/pose/rel_alt/hdg/fix（后台 MultiThreadedExecutor spin +
   BEST_EFFORT QoS），等脚本退出（带 timeout，超时 kill 记 rc=-999）。
5. **判定 + 报告**：checks 列表逐项 PASS/FAIL，任何一项 FAIL → 退出码 1。

## 4. 验收标准（以计划书 §2 为准，写进 verify 脚本 docstring）

通用（每脚本必查）：
- a. 被测脚本退出码 0，日志无 `[ERROR]`（`[WARN]` 必须逐条给出解释）。
- b. 起飞达标（rel_alt/local z 峰值达目标 - 容差）。
- c. 前飞距离在目标 ±40%（计划书给的区间）。
- d. 前飞方向与罗盘航向误差 ≤45°（ENU/NED 换算正确性）。
- e. 收尾自动上锁 armed=False；最终模式合法（该脚本规定的模式）。
- f. 模式序列无 FAILSAFE/RTL（除非该脚本的终点就是 RTL）。
- g. 全程无 FAILSAFE；异常路径不触发（能测就测）。
- h. **高度门控参考系一致（#40）**：门控通道的零点必须与命令/期望的零点同源——
  `MAV_CMD_NAV_TAKEOFF` 的 altitude 相对 Home，故门控用 `rel_alt`（可加地面
  `ground_rel_alt` 基准），**不得**裸用 `pose.z`（它是 "EKF 局部原点以上高度"，
  不是离地高度）。高度类断言必须带**独立真值**（Gazebo `iris_demo.z`），
  禁止拿飞控自身通道互证；排查/量化用 `scripts/verify_takeoff_alt.py`。
  - 视觉 `detector_node` 底部栏须**同时**显示 `Zpose`（pose.z）与
    `RelAlt(true)`（rel_alt）；**cv2 Hershey 字体只能渲染 ASCII**，标签禁用中文
    （会变 `?`），且行宽受左栏限制会被截断。
- i. **航段容差 < 航段长度（#41）**：到点判据的 `*_tolerance`/`*_radius` 若 ≥ 航段长度，
  会"未移动即判到达"（空飞）。改短航段/小距离任务时**连带检查所有容差**（水平与垂直）。

脚本专属（示例 C2）：WGS84 目标抵达（水平误差 ≤1m、悬停 ≥4s）、
RTL 返回起飞点 ≤2m 再上锁、授权短语输错 → 退出码 2 且零副作用（可选负例）。

## 5. 自测 → 演示（两遍跑法）

1. **自测遍**：我完整跑 verify，FAIL 就修，修完重跑，直到全 PASS。
   期间不打扰用户。
2. **演示遍**：全 PASS 后再跑一次**真实仿真飞行**给用户看（用户要求：
   "翻译完成后在仿真里面跑给我看"）：
   - 起飞前告诉用户看哪个窗口（Gazebo Sim 主视角 + 右上相机窗）；
   - 演示前 30 秒内再跑一次 preflight 确认全绿；
   - 演示日志 `tee /tmp/opencode/cX_demo.log`；
   - 演示遍同样全 PASS 才算交付，随后归档台账。
