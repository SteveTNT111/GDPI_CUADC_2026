## 一、AP 里的 EK2 / EK3 是什么？（AI生成回答）

- **EK2 = EKF2，EK3 = EKF3**，都是飞控里的「状态估计器」，学名叫**扩展卡尔曼滤波（EKF）**。
- 它们干的事：把飞控上一堆传感器（IMU 加速度计/陀螺、气压计、罗盘、GPS/RTK、空速……）**融合**到一起，算出飞机当前最可信的：
  - 姿态（横滚/俯仰/航向）
  - 位置（经纬度 / 本地 XY）
  - 速度
- 可以理解成：**传感器给的都是「各有误差的线索」，EKF 负责综合出唯一答案。** 没有 EKF（或 EKF 不健康），飞控就不敢解锁、不敢自动飞。
- **EK2 是第一代，EK3 是新一代**。ArduPilot 4.x（我们用的 4.7.1）默认用 EK3。
- 参数名的小知识：固件源码里写的是 `EKF2_` / `EKF3_`，但飞控参数名有长度限制，所以参数表里显示成 **`EK2_` / `EK3_`**。所以 `EK2_ENABLE` = `EKF2_ENABLE`，`EK3_ENABLE` = `EKF3_ENABLE`，是同一个东西。
- 用哪个当「主估计器」由参数 **`AHRS_EKF_TYPE`** 决定：`2` = 用 EKF2，`3` = 用 EKF3。

## 二、为什么要把 EK2_ENABLE 设为 0？

简单说：**两个 EKF 只要留一个（EK3），另一个关掉。** 原因有三条：

1. **省资源**：两个都开着会同时占用 CPU/内存，多旋翼飞控算力本来就紧张，没必要。
2. **EK3 才是我们要用的那个**：4.x 默认 `AHRS_EKF_TYPE=3`、`EK3_ENABLE=1`、`EK2_ENABLE=0`。EK2 是老的，很多新功能（尤其是下面这条）它没有。
3. **双天线 RTK 定航向（GPS Yaw）只有 EK3 支持**：
   - 双天线 RTK（我们的 UM982）能用两根天线直接算出**机头朝向**，参数是 `EK3_SRC1_YAW=GPS`。
   - **EKF2 不支持这个**，它只能靠罗盘定航向——罗盘一被干扰就报「compass not healthy」。
   - 所以想让双天线 RTK 接管航向、绕开罗盘问题，就必须用 EK3，把 EK2 关掉。

**⚠️ 重点提醒（别踩坑）：**
- 只把 `EK2_ENABLE` 改成 0，**并不会直接修好** `compass 1 not healthy`。它只是保证「用 EK3 而不用老的 EK2」。
- 真正要让 RTK 替代罗盘，通常是一整套动作，比如：`AHRS_EKF_TYPE=3`、`EK3_ENABLE=1`、`EK2_ENABLE=0`、`EK3_SRC1_YAW=GPS`（双天线才有效），必要时再配合罗盘相关参数（如 `COMPASS_USE`、`ARMING_CHECK`）。**单改一个参数，故障大概率还在。**
- 改完记得**重启飞控**才生效。

## 三、飞控的全部参数表存在哪儿？拉下来是什么格式？

### 1. 参数存在哪儿
- **飞控板上**：所有参数保存在主板上的**非易失存储器**（EEPROM / FRAM，CubePilot 系是 FRAM），**掉电不丢**。这张「完整参数表」长什么样，是**固件代码里定义好的**（ArduPilot 的 `AP_Param` 机制）。
- **官方完整参数表（在线版）**：ArduPilot 官网有 **Complete Parameter List（完整参数列表）**，是按固件版本自动生成的网页，可以按名字查每个参数的默认值和含义。要查某个参数「官方定义是什么」，去这里最靠谱。
- **本地查看/导出**：
  - Mission Planner：`CONFIG/TUNING → Full Parameter List` 或 `Full Parameter Tree`，点 **Save** 就能存成 `.param` 文件。
  - MAVROS（我们机载电脑用这个）：用 service 拉取，命令见下。

### 2. 用 MAVROS 拉取全部参数
```bash
rosservice call /mavros/param/pull "force_pull: true"
```
成功返回示例：
```text
success: True
param_received: 1143
```
`param_received: 1143` 就表示从飞控拿到了 **1143 个参数**。

读单个参数：
```bash
rosservice call /mavros/param/get "param_id: 'EK3_ENABLE'"
rosservice call /mavros/param/get "param_id: 'AHRS_EKF_TYPE'"
```

### 3. 拉下来是什么格式
分两层看，别搞混：

- **传输过程中**：是 MAVLink 的 **`PARAM_VALUE` 消息**，里面装着 `param_id`（名字）、`param_value`（值）、`param_type`（类型）、`param_index` / `param_count`（第几个、共几个）。飞控是一个一个把参数「报」出来的，不是一整个文件。
- **存成文件后**：是**纯文本**，不同软件格式略有差别：
  - **ArduPilot / Mission Planner 的 `.param`**：每行一个参数，`参数名,值`，逗号分隔，例如：
    ```text
    EK3_ENABLE,1
    EK2_ENABLE,0
    AHRS_EKF_TYPE,3
    ```
    （这是最通用的交换格式，比赛备份参数就用它。）
  - **QGroundControl 的 `.params`**：每行用制表符分隔，`序号  序号  参数名  值  类型`。
  - **MAVROS 拉取后**：参数进入 `/mavros` 的参数空间，可以用 `rosparam` 读、也可以 `rosparam dump` 存成 YAML；但**要备份/和别人交换，建议还是存成 `.param`（逗号分隔）**，最通用。

### 4. 一句话总结
> 参数表在飞控的掉电存储里，也在固件代码里定义着；要「一整个文件」得自己用 Mission Planner 的 Full Parameter List 导出，或用 MAVROS 的 `/mavros/param/pull` 拉取后存成 `参数名,值` 的文本（`.param`）。

# 补充：Pixhawk v6x 的 GPS1 是哪个串口？波特率怎么设？

> 参考《NRTK-2 用户手册》第 12 页「5.1 APM 飞控配置」。

## 一、结论（一句话）
- **飞控参数层面：GPS1 接口 = `SERIAL3`（第 3 号串口），GPS2 = `SERIAL4`。**
  - 所以你调 GPS1 的波特率，就是改 **`SERIAL3_BAUD`**，不是别的。
  - 不用去纠结底层 STM32 是哪个 UART，固件里「丝印 GPS1 的口 ↔ SERIAL3」是固定映射。
- **接线：NRTK-2 模块的 UART2 → 飞控的 GPS1 口**（手册原文就是这句）。

## 二、参考 NRTK-2 手册，要改的参数（APM / ArduPilot）

```text
SERIAL3_PROTOCOL   = 5        # GPS 协议
SERIAL3_BAUD       = 230400   # ★波特率就改这里
GPS1_TYPE          = 25       # 25=启用双天线测向；24=不启用
GPS2_TYPE          = 0
GPS_AUTO_CONFIG    = 1
GPS_AUTO_SWITCH    = 1
```

若启用双天线测向，再加：
```text
GPS1_MB_TYPE       = 1
GPS1_MB_OFS_X      = 0.00   # 单位:米, 前+ / 后-
GPS1_MB_OFS_Y      = 0.00   # 右+ / 左-
GPS1_MB_OFS_Z      = 0.00   # 下+ / 上-
AHRS_EKF_TYPE      = 3
EK2_ENABLE         = 0
EK3_ENABLE         = 1
EK3_SRC1_YAW       = 2
```

## 三、GPS1_MB_OFS_X/Y/Z 到底怎么填？（双天线基线偏移）

**含义**：两根天线的**相对位置**（术语叫 moving baseline 杆臂 offset）。飞控拿它把 RTK 测出的航向正确地挂到机身上，所以方向和符号非常关键。

**规则**（ArduPilot 机体坐标系，单位是「米」，不是厘米！）：
- **X：机头方向为正**（副天线在主天线前面 → 正，后面 → 负）
- **Y：右为正**（副天线在右边 → 正，左边 → 负）
- **Z：下为正**（副天线比主天线低 → 正，高 → 负）
- **参考点**：以**主天线（primary/master）为中心**，指向**副天线（secondary/slave）**。

**怎么量**：拿卷尺量主、副两个天线中心之间的「前后 / 左右 / 上下」三个差值，带上符号填进去即可。

**例子**：
- 两天线沿机身中线一前一后装，副天线在主天线**正后方 0.5 m**：
  ```
  X = -0.50   Y = 0.00   Z = 0.00
  ```
- 两天线左右横着装（比如装在两个机臂上），副天线在主天线**右侧 0.5 m**：
  ```
  X = 0.00   Y = 0.50   Z = 0.00
  ```
- 副天线在主天线**左前方、略高**：前 0.30 m、左 0.40 m、高 0.05 m：
  ```
  X = 0.30   Y = -0.40   Z = -0.05
  ```

**填完必须验证（这一步比量得多准更重要）**：
- 通电后看飞控航向（heading），把机头对准一个已知方向（手机指南针 / 跑道中线），看 RTK 航向对不对。
- **航向反了 180°**：多半是主、副天线**接反了**（对调两个天线接口），或 X 符号填反。
- **航向差一个固定角度（比如总差 90°）**：检查天线是不是横着装的、Y 的符号对不对。
- 数值**厘米级精度就够**，不用很精确；**关键是方向和符号别搞反**。

## 四、几个要注意的点
- **230400 是模块和飞控两边必须一致的波特率**。模块 UART2 出厂/手册默认就是 230400；如果模块被改过而飞控没改（或反过来），表现就是**收不到数据 / 定位不动 / 不显示 Fix**。
- **改完参数要重启飞控**才生效。
- 设好后在 Mission Planner 看 GPS 状态：应有 **3D Fix / RTK Fix**。
- 顺便对照：NRTK-01 手册也是「serial3 = GPS1，serial4 = GPS2，波特率 230400」，两块模块结论一致。
